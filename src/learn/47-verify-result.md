# 验证结果模板

验收不是问“做完了吗”，而是检查实际产物是否符合要求。把验证项目写具体，才能区分完成、失败和没有条件验证。

```text
请对照本次需求检查最终结果，不继续扩展功能。

验收项：[逐项列出用户可观察的行为]
范围：[文件、页面、接口或模块]
可用环境：[浏览器、测试服务或运行条件]

请先查看实际文件和项目已有检查命令，再执行合适的验证。
结果按以下内容报告：
1. 主要改动和对应需求。
2. 实际执行的命令、检查动作和结果。
3. 通过、失败、未执行的项目分别有哪些。
4. 未执行的原因，以及需要谁补充什么条件。

不要把计划执行写成已经执行，不隐藏失败。
发现新问题先记录，不擅自扩大修改或发布。
```

## 网页验收例子

要求不是“页面没问题”，而是：“姓名正确；三条兴趣完整；375 像素宽度没有遮挡；按钮链接正确；没有新增依赖”。

如果没有浏览器，只能做文件引用和静态内容检查，就把布局预览列为未执行。构建通过也不能证明所有点击流程正常。

实际跟练：把上面五项网页要求填入模板，指定当前 `index.html` 和 `style.css`，发送后逐项对照。报告至少应说明依据来自文件、命令还是浏览器；然后你自己打开页面复查一次，不只接受一句“均通过”。

如果用的是 JavaScript 练习包，验收项换成语法检查和任务计数测试，并要求列出真实运行命令与通过/失败数。不要对纯静态页强行要求不存在的测试命令。

**完成标准：** 验收结果有证据，失败和限制可见，下一位接手的人知道还需要检查什么。
