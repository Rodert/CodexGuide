# 推荐工具与资源

初学时不需要一次装齐所有工具。先准备能编辑、预览和保存版本的基础环境，需要处理具体问题时再补充。

## 第一阶段：做出并检查作品

| 工具 | 用来做什么 |
| --- | --- |
| 浏览器及开发者工具 | 预览页面，查看控制台和资源加载错误 |
| 文本编辑器 | 阅读 HTML、CSS 和配置文件 |
| Git | 保存版本、查看差异，便于恢复 |
| 终端 | 运行项目提供的启动、测试和构建命令 |

这些工具与 Codex 配合使用。即使主要让 AI 修改，也应能独立找到文件、打开结果和看懂基本错误提示。

可以先完成三件小事：用文本编辑器打开 `index.html`，用浏览器看到同一页面，再按 Git 教程保存一个版本。三件事能自己完成，就具备继续跟练的基础；暂时用不到的工具不必先安装。

## 第二阶段：按项目补工具

做前端时，根据项目要求安装 Node.js 和对应包管理器；做其他语言项目，则使用它要求的运行时。不要为了一个静态网页练习先装完整套容器、数据库和云服务。

本教程的 [JavaScript 练习包](/examples/js-practice.zip) 使用 Node.js 自带测试能力，需要 Node.js 22 或更高版本。安装后新开终端，用 `node --version` 和 `npm --version` 确认工具可见；再进入解压目录运行 `npm test`，初始应通过 1 个用例。不需要额外安装测试框架。

插件和 Skill 也按需安装。判断标准是它是否解决当前重复出现的问题，而不是名称多、数量多。

## 值得收藏的资料

- [Codex 官方文档](https://developers.openai.com/codex/)：核对产品能力和使用入口。
- [MDN Web Docs](https://developer.mozilla.org/zh-CN/)：查询 HTML、CSS、JavaScript 和浏览器行为。
- [Git 官方书籍](https://git-scm.com/book/zh/v2)：理解版本记录、分支和协作。
- 项目自身的 README、依赖声明和测试：理解当前项目最直接的依据。

安装软件和扩展时优先使用官方渠道，不把营销页面当作技术验证。涉及第三方账号、凭证或代码上传时，先读清楚数据和权限说明。

## 学完之后做什么

选一个自己真正需要的小工具，按“说清目标、分步实现、验证结果、保存版本”的节奏完成。遇到新问题，再回到对应章节查，而不是先把所有功能学完才开始动手。
