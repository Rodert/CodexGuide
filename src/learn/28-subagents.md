# 子代理

子代理可以理解为主任务临时安排的协作者。主任务负责拆分、汇总和验证，其他代理处理边界清楚的子问题。是否支持、如何启用和如何计费，要看当前入口及账户设置。

## 什么任务适合拆开

同一个网页，可以分别检查 HTML 结构、CSS 布局和链接。这些检查相对独立，结果也容易汇总。

如果几个步骤有先后依赖，例如先确定接口格式再实现前端，就不能仅为了“并行”而同时开始，否则容易做出互不兼容的结果。

## 先从并行只读检查开始

在确认支持该能力的环境中，可以这样描述：

```text
请拆分为独立的只读检查：
1. 检查 HTML 结构和资源引用。
2. 检查窄屏样式可能的问题。
3. 检查联系链接和可访问性。
各自报告文件位置和依据，由主任务去重汇总。
先不修改文件；不支持子代理时顺序完成并说明。
```

## 为什么多个代理仍会出错

它们可能基于不同理解给建议，或重复报告同一个问题。多个代理同时改同一文件，还可能相互覆盖。分配修改任务时，要明确各自文件和接口边界。

主任务需要重新检查证据和最终差异，不能只把几份报告拼起来就算完成。代理数量增加也可能增加等待、用量和协调成本。

**完成检查：** 每个子任务有独立目标、输入和结果，最后有统一验收。具体开关和参数暂不提供未经版本核对的示例。
