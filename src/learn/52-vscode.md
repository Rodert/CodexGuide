# VS Code 问题

编辑器中的问题先检查扩展、工作区和运行环境。尤其在远程 SSH、容器或子系统中，编辑器界面和项目命令可能不在同一台主机上运行。

## 看不到 Codex 入口

先确认安装的是官方说明指向的扩展、发布者正确、扩展已启用。查看是否被工作区、组织策略或当前编辑器兼容性限制。按界面提示重新加载窗口，再查看扩展状态。

## 能聊天，但读错项目

确认打开的是完整项目目录，而不是一个单独文件。多根工作区里可能同时有几个项目，任务中明确目标目录和文件。

先用“文件 → 打开文件夹”打开练习目录，在左侧确认文件名；再用“终端 → 新建终端”查看终端起始目录。远程窗口还要确认命令确实运行在目标环境，不能只看本机浏览器能否打开页面。

先测试：

```text
只读分析：说明当前项目的工作目录，
解释 index.html 与 style.css 的关系，列出读取的文件。
不要修改文件或安装依赖。
```

结果与实际不符时，先修正工作区，别在错误目录继续执行。

## 修改后看不到结果

查看文件是否保存、Diff 是否仍有待处理项、预览服务是否指向当前目录。打开的网页也可能来自另一个运行中的项目。

如果扩展调用终端失败，保留命令和输出；如果是扩展自身报错，查看编辑器提供的扩展日志或输出面板。两者需要不同信息。

普通文件修改后可用 Windows 的 `Ctrl+S` 或 macOS 的 `Command+S` 保存，再刷新页面。如果 Diff 中并没有实际变化，就先检查修改是否应用，而不是反复重启预览服务。

**完成检查：** 确认当前扩展状态、运行环境和目标文件，再恢复修改任务。
