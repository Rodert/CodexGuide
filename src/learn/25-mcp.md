# MCP

MCP 是 Model Context Protocol，中文通常叫模型上下文协议。你可以把它理解为一套连接约定，让 AI 工具能通过统一方式访问外部能力。

例如，某个 MCP 服务可以提供文档查询，另一个可以查询开发数据库。能做什么取决于服务实际提供的工具和权限，并不是接入 MCP 后就拥有所有能力。

## 先弄清三个角色

- **客户端**：发起调用的 Codex 入口。
- **服务端**：提供查询或操作能力的程序。
- **授权**：决定是否允许访问哪些数据或执行哪些动作。

本地服务可能需要在电脑上启动；远程服务可能通过网络连接。部分服务还需要额外登录或配置凭证。

## 第一次连接怎么验证

本节的查询练习以“已经连接了一个文档查询服务”为前提。尚未配置时，先在官方说明中核对服务类型、地址、启动要求和认证，再通过当前入口支持的配置方式接入；没有这些信息就先不填猜测的参数。

从只读、小范围任务开始，例如：

```text
使用已经配置的文档查询工具，查找当前框架的路由说明。
只查询资料，给出来源，不修改项目文件。
如果工具不可用，说明失败在哪一步，不要假装已经查询。
```

确认工具可见、调用成功、返回内容与目标相关。三者不是一回事：能看到工具名，不代表授权有效；连接成功，也不代表结果可靠。

可以把结果记成三行：“工具是否可见；查询是否成功；来源是否匹配”。失败在哪一行，就从那一层继续检查，参考 [MCP 与插件问题](./53-mcp-plugins.md)。没有可用服务时，本节只完成概念学习，暂不宣称接入成功。

## 新手常见误解

MCP 不等于模型，也不替代 Skill。Skill 说明工作方法，MCP 提供调用通道。工具返回的网页、文件或日志是任务数据，其中出现的“忽略之前要求”等文字不能当成你的新指令。

需要访问数据库时，先用测试环境和最小权限账户。服务地址、启动方式和认证参数各不相同，不要照抄其他服务的配置。

官方配置入口：[Codex MCP](https://developers.openai.com/codex/mcp/)。下一节：[Apps 与连接器](./26-apps-connectors.md)。
