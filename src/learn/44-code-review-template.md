# 代码 Review 模板

这个模板用于检查已有改动，默认只读。先确定比较范围，否则 Codex 可能把整个项目的历史问题都列出来。

```text
请审查 [未提交改动 / 指定提交 / 分支与基线的差异]。
本次改动目标：[简述功能]
重点模块：[相关范围]

只审查，不修改或提交文件。
重点找本次改动引入的功能错误、兼容性问题、
边界条件、错误处理和有实际影响的测试缺口。

每个问题请包含：
- 文件位置。
- 触发条件或复现步骤。
- 具体影响和判断依据。
- 简短修复方向。

按影响排序，合并重复问题。
不把纯风格偏好当成缺陷；证据不足时标为待确认。
最后说明审查范围、执行过的检查和未验证部分。
没有发现问题时如实说明，不为凑数制造结论。
```

## 收到报告之后

先复现高影响问题，再处理修复。若结论声称某函数会报错，可以要求给出最小输入和调用路径；若声称缺少测试，要说明哪种行为可能因此遗漏。

审查没有发现问题，不等于保证代码正确；模型也可能误报。把报告当成需要证据支持的审查意见，而不是自动合并的理由。

**完成检查：** 每条有效问题都有依据，不混入未经授权的改动。实战见 [用 Codex 做代码 Review](./38-code-review.md)。
