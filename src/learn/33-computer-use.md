# 浏览器与电脑操控

改好代码后，还要查看实际页面。浏览器工具可以帮助检查网页内容和交互；电脑操控则可能覆盖桌面应用、系统对话框等更广范围。是否可用取决于当前入口、已安装工具和授权。

## 检查代码和检查页面有什么不同

HTML 中存在一个按钮，不代表按钮能被看见或点击。它可能被遮挡、指向错误地址，或在手机宽度下跑出屏幕。

因此，网页任务最好同时检查文件和运行结果。

## 用个人网页做练习

先手工打开网页，确认能访问；不会预览时回看 [检查任务结果](./08-review-result.md)。然后确认当前 Codex 已有浏览器工具，再要求它使用你明确指定的文件或预览地址。

在确认当前环境可以打开页面后，可以这样描述：

```text
预览当前个人介绍网页，检查宽屏和约 375 像素窄屏。
确认姓名、兴趣和联系按钮可见，页面没有横向溢出。
检查联系链接地址，不发送邮件。
先报告问题，不修改文件；无法打开页面时说明原因。
```

如果工具不能直接打开本地文件，可以使用项目支持的本地预览方式。不要让它仅凭阅读 CSS 就声称“已经在浏览器测试通过”。

你也可以手工验证：浏览器打开开发者工具的设备预览模式，将宽度设为 375 像素，再检查按钮和文字。检查后把实际看到的问题发给 Codex；没有浏览器工具并不妨碍这一步学习。

## 使用已有登录状态要小心什么

浏览器中可能已经登录了工作账号。点击发布、发送、购买或删除，会产生真实影响。任务应明确目标页面和允许动作，读取页面不等于允许提交表单。

截图和网页内容也可能包含账号、路径和隐私。教程截图先使用虚构数据，再检查是否需要打码。

**完成检查：** 报告应区分实际观察、推测和未测项目，并注明检查过的页面或窗口宽度。
