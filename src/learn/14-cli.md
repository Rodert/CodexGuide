# Codex CLI

## 适合谁

日常会使用终端、需要在本地项目目录中工作，或希望后续接入脚本和自动化流程的读者。

## CLI 是什么

CLI 是在终端中使用 Codex 的方式。它不要求你离开项目目录：进入一个仓库后，启动 Codex，说明任务，检查它修改的文件和运行结果即可。

与桌面 App 相比，CLI 更适合已经有代码仓库和命令行习惯的开发者；与 VS Code 相比，它更适合希望把工作放在终端、脚本或远程环境中的人。

## 开始前

使用 CLI 前，准备好三样东西：

1. 一个可打开的终端。
2. 一个练习目录或 Git 项目。
3. 正常可用的 Codex 登录方式。

第一次使用时，不要直接进入最重要的项目。先在空目录或可回退的练习仓库中熟悉“说明任务、确认动作、检查结果”的流程。

## 基本工作节奏

### 进入项目目录

先在终端进入你希望 Codex 处理的目录。工作目录是最重要的边界之一：如果目录不对，后面的读写和命令执行范围也会跟着不对。

### 说明一个小任务

从能验证的任务开始，例如“解释这个项目有哪些主要文件”，或“为这个示例页面增加一个标题”。先让 Codex说明它理解的范围，再允许它执行修改。

### 检查改动

任务完成后，查看它的总结、文件改动和命令输出。对于代码项目，还应该使用项目自己的测试、预览或 Git Diff 来确认结果。

## 桌面 App、CLI 和 VS Code 怎么选

- 第一次体验与低代码任务：优先桌面 App。
- 终端和本地仓库工作：优先 CLI。
- 长时间在编辑器里写代码：优先 VS Code。

它们的入口不同，但安全习惯相同：确认目录、讲清范围、理解权限、检查结果。

## 常见问题

**命令找不到怎么办？** 先查看 [CLI 问题](./51-cli.md)，确认安装、终端重启和系统路径设置。

**能在真实项目中直接用吗？** 可以，但建议先查看 Git 状态，明确本次要改的范围，并在提交或发布前自行验证。
