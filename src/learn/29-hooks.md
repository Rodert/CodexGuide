# Rules 与 Hooks

Rules 和 Hooks 都与约束工作流程有关，但作用不同。先分清“给 AI 的说明”和“由程序执行的机制”，才不会把一句要求误当成技术保障。

## 三种约束怎么区分

| 方式 | 作用 | 例子 |
| --- | --- | --- |
| 项目说明 | 告诉 Agent 应怎样工作 | AGENTS.md 中要求修改后测试 |
| 执行规则 | 按工具支持的规则判断命令 | 对某类操作要求审批或拒绝 |
| Hook | 在指定事件发生时运行程序 | 在受支持事件后执行检查 |

不同工具对 Rules 的叫法并不统一。不要把其他编辑器的规则文件直接改名，就认为 Codex 一定能识别。

## 先把检查做成普通命令

假设想在修改后检查格式，先确认项目已有的格式检查命令可以手工运行。只有它在正常环境中工作，才考虑由 Hook 触发。

可以下载 [JavaScript 练习包](/examples/js-practice.zip)，解压并准备 Node.js 22 或更高版本，在该目录的终端运行 `npm run check`。正常退出表示这次语法检查通过，但不代表业务行为正确；再运行 `npm test` 检查已编写的用例。

先记住这两条命令分别检查什么。将它们接到 Hook 上，是后续需要核对事件与配置的独立步骤；本轮不要把“命令跑通”记成“Hook 已启用”。

下面只是流程示意，不是可复制的配置：

```text
受支持的事件发生
→ 运行项目检查程序
→ 读取退出状态和输出
→ 按该事件支持的方式继续、提示或阻止
```

Hook 能触发哪些事件、是否能够阻断动作，取决于实际实现。不能假设所有 Hook 都像提交前检查一样工作。

## 新手从哪里开始

先在 `AGENTS.md` 写清流程，再把重复检查整理成独立命令。需要自动触发时，核对当前版本的事件、配置和失败处理方式，然后在练习项目测试。

不要把密钥写进脚本，也不要把自动删除或上传作为第一个 Hook 练习。本节暂不提供未经核对的 Hook 配置字段。

参考：[Codex 高级配置](https://developers.openai.com/codex/config-advanced/)。下一节：[Worktrees](./30-worktrees.md)。
