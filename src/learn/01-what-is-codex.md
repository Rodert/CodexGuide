# 认识 Codex

## 适合谁

第一次听说 Codex，或者已经打开过界面、但不知道第一句话该怎么说的读者。

## 开始前

先记住一件事：Codex 不是只给出代码建议的聊天窗口。它可以在你允许的工作目录中阅读文件、修改文件、运行命令，并把执行过程和结果展示给你。

这也意味着它不应该被当作“按一下就一定正确”的自动机器。无论任务大小，最后都要由你检查文件、预览结果或运行测试。

## Codex 能帮你做什么

对第一次使用的人来说，最常见的任务有四类：

- **从零创建小作品**：例如生成一个个人介绍网页、一个待办清单，或一个简单脚本。
- **阅读和解释项目**：让它先说明一个文件、一个报错或一个功能模块在做什么。
- **修改已有内容**：例如调整网页文字、修复一处已知报错，或补一段测试。
- **协助完成重复工作**：例如整理项目说明、生成文档初稿、检查代码改动。

开始时，优先选择结果容易看见、影响范围很小的任务。一个空文件夹里的练习网页，比直接让它改工作项目更适合建立第一感觉。

## Codex 不会替你承担什么

Codex 可以帮你执行工作，但不能替你决定业务目标，也不能保证每次修改都符合你的真实要求。尤其在下面几种情况里，需要放慢一步：

- 任务涉及真实客户数据、密钥、账号或生产环境。
- 任务会删除、批量改写或向外部服务发送数据。
- 结果需要上线、提交代码或交付给其他人。

遇到这些场景，先让它解释计划和影响范围，再决定是否允许执行；完成后再看 Diff、预览或测试结果。

## 第一次建议做什么

第一次不需要准备一个真实项目。后面的教程会带你创建一个单独的练习文件夹，并让 Codex 生成一个简单网页。这个任务会让你同时看到：工作目录、任务描述、文件创建、结果预览和后续修改。

## 常见问题

**不会写代码也能开始吗？** 可以。先从“创建一个网页”或“解释一个文件”这类任务开始，同时把每一步的结果看清楚。真正涉及项目代码时，再补齐 Git、测试和权限相关知识。

**一开始应该使用桌面 App 还是 CLI？** 完全新手优先从桌面 App 开始，操作更直观。熟悉任务流程后，再进入 CLI 和 VS Code 专题。
