# 第一次修改项目

第一次让 Codex 修改已有项目，从范围小、结果容易检查的任务开始。例如改网页文案、调整按钮样式，而不是同时更换框架、目录和接口。

## 开始前确认

选对工作目录，查看已有修改，知道项目如何预览。真实项目最好先有可回退的版本；不要要求 Codex 自动覆盖别人的未提交内容。

## 可以直接复制的模板

```text
请在当前项目完成一个小修改。

目标：[用户能看到的变化]
范围：[相关文件或模块]
保持不变：[已有功能、接口和内容]
限制：[技术约束、不要新增的依赖]
验收：[具体操作和预期结果]

先查看当前文件和 Git 状态，说明相关位置。
保留已有未提交改动；发现重叠时先说明。
只实现本次目标，完成后列出改动与验证结果。
未执行的检查要明确写出，暂时不要提交或发布。
```

网页练习中可以填：“把联系按钮改为蓝色；只改样式；保留链接和文字；刷新后宽窄屏都能看见按钮”。

第一次使用按四步做：打开个人网页目录；把上述内容填进模板并删掉方括号；整段发送给 Codex；完成后打开同一目录的网页并刷新。没有作品时先解压 [练习包](/examples/personal-page.zip)，不要在教程网站仓库里直接改示例文件。

预期改动集中在按钮样式，原有链接仍是 `mailto:hello@example.com`。只给出建议却未保存时，要求它确认是否实际写入文件。

## 完成后怎么看

对照需求预览，再看文件差异。如果任务只是改按钮，却出现大量依赖和配置改动，先让它解释必要性，再决定是否保留。

这个模板适合边界清楚的小改动。原因不明的故障先用 [先分析再修改](./41-analyze-first.md)，不要把排查和大范围重写混在一起。
