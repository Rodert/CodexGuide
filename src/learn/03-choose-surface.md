# 选择使用方式

## 适合谁

知道 Codex 可以从多个入口使用，但不知道第一次应该打开哪个入口的读者。

## 开始前

不要把“入口”理解成不同的产品。它们更像是同一类工作方式的不同操作界面：有人更习惯点选项目，有人离不开终端，也有人希望始终留在编辑器里。

## 四个入口怎么理解

### 桌面 App：第一次体验最直观

桌面 App 适合想看见项目、对话、文件修改和权限提示的读者。第一次完成网页或小工具任务时，图形界面能帮助你把“工作目录、任务、结果”联系起来。

**适合你，如果你：**

- 第一次使用 Codex，不熟悉终端。
- 想先在单独的练习文件夹里完成任务。
- 希望通过界面查看对话、文件和改动。

### CLI：适合已经使用终端和项目目录的人

CLI 在终端里运行。它更接近开发者日常的命令行工作方式，适合在本地项目、脚本和自动化流程中使用。

**适合你，如果你：**

- 已经会打开终端、进入项目文件夹。
- 希望在命令行中完成阅读代码、修改文件和运行测试。
- 后续需要脚本化或接入 CI。

### VS Code：适合主要在编辑器里写代码的人

如果你的工作大部分时间都在 VS Code 中完成，编辑器入口能减少在窗口之间切换。你可以围绕当前文件、选中代码和项目上下文发起任务，再检查修改结果。

**适合你，如果你：**

- 日常使用 VS Code 或兼容编辑器。
- 想让 Codex 和打开的文件、代码选择一起工作。
- 更习惯在编辑器里审查改动。

### Cloud：适合需要远程或并行处理任务的人

Cloud 适合把任务交给远程环境执行、跟进任务状态或处理与远程仓库相关的工作。它并不是第一次体验 Codex 的必要条件，先完成本地任务后再学习会更轻松。

**适合你，如果你：**

- 有远程仓库或需要长时间运行的任务。
- 想把本地工作和远程任务分开。
- 已经理解项目、权限和结果验证的基本流程。

## 第一次怎么选

如果你完全没有使用经验，按下面的顺序即可：

1. 先用桌面 App 完成本教程的第一个网页任务。
2. 如果你平时写代码，接着学习 CLI 或 VS Code。
3. 需要远程仓库和并行任务时，再进入 Cloud 专题。

入口可以切换，但“先说明任务、确认范围、检查结果”的工作习惯不变。

## 常见问题

**必须四个入口都会吗？** 不需要。选择一个最接近日常工作方式的入口即可；其他入口可以在需要时再学习。

**桌面 App 和 VS Code 会不会重复？** 两者都能处理本地项目，但侧重点不同：前者更适合独立的任务和项目管理，后者更贴近编辑器内的代码阅读和修改。
