# 模型选择

选模型先看任务，而不是只看名称。当前入口可用哪些模型、支持哪些设置，要以实际列表和官方说明为准；本节不列容易过期的型号排名。

## 用任务难度做选择

| 任务 | 选择思路 |
| --- | --- |
| 改文案、解释小段代码 | 优先考虑响应速度与用量 |
| 常规功能、补测试 | 观察能否遵循项目规范并完成验证 |
| 多文件排错、复杂设计 | 更重视推理、工具使用和跨文件分析表现 |

模型能力只是结果的一部分。缺少复现步骤、文件权限或依赖环境时，换模型不一定解决问题。

## 怎样比较才有意义

准备同一份代码、同一条任务和同样的验收要求，分别观察：

1. 是否找到真正相关的文件。
2. 是否保留了要求不变的行为。
3. 是否实际执行检查并解释失败。
4. 修改量、等待时间和使用成本是否能接受。

不能只因为回答更长、语气更肯定，就判断结果更好。

## 推理设置越高越好吗

如果入口提供推理强度选项，可以把它理解为影响分析投入的一种设置。更高设置不保证每个任务都更准确，也可能增加等待和资源消耗。简单改字先保持默认；复杂任务再比较实际结果。

遇到重复失败，先补齐目标、范围、复现和验收，再考虑换模型。不要在同一时间同时更换模型、配置和提示词，否则难以判断是哪一项起作用。
