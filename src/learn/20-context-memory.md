# 上下文与记忆

上下文是 Codex 当前处理任务时能参考的信息，例如你的要求、读取过的代码和命令输出。它可以帮助连续工作，但不等于无限、永久、准确的项目记忆。

## 为什么聊久了容易跑偏

一个对话里同时出现旧方案、新要求和多个功能，当前目标就难以辨认。任务越长，也越不能假设很早以前的每个细节都会原样保留。

解决方法是提供准确的信息，而不是不断追加整段历史：

```text
当前目标：只修复手机上联系按钮被遮挡的问题。
相关文件：index.html、style.css。
保留要求：不要改变桌面布局，不新增依赖。
之前的深色主题方案已取消，以当前文件为准。
```

## 什么放在哪里

| 信息 | 合适的位置 |
| --- | --- |
| 这次要改什么、怎么验收 | 当前任务描述 |
| 长期的项目规范和检查命令 | AGENTS.md |
| 项目现状与重要设计结论 | README 或项目文档 |
| 某个报错的证据 | 相关日志、复现步骤和文件位置 |

产品可能提供额外的记忆功能，但不能把它当成团队规范的唯一保存位置。重要结论写进项目，其他人和新任务才有依据。

## 什么时候新建对话

目标已经变了、旧方案干扰判断，或需要反复纠正前文时，可以新建对话。先让旧任务整理交接摘要：目标、已改文件、验证结果、剩余问题和明确的限制。

交接后让新任务重新检查实际文件。摘要是线索，当前代码和可复现结果才是判断依据。

**小练习：** 用五句话写出网页项目的交接摘要，检查新对话能否据此继续处理同一个问题。
