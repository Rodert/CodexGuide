# 权限与沙盒问题

遇到 `Permission denied`、只读文件或网络拒绝时，先找出失败动作和约束来源。权限报错不是统一的“Codex 没有权限”。

## 四种情况分别看

| 情况 | 排查方向 |
| --- | --- |
| 操作系统拒绝读写 | 文件所属用户、访问权限或目录位置 |
| 沙盒禁止越界 | 当前允许的工作范围 |
| 审批未通过 | 请求的动作、目标和审批状态 |
| 外部服务拒绝 | 登录账户、令牌范围或服务策略 |

外部服务返回 403 也可能涉及账号或服务策略，不能仅凭这一条就认定是本地沙盒。

## 收集证据再处理

```text
请分析这次权限失败，先不修改安全设置。
失败命令和工作目录：[内容]
目标文件或服务：[脱敏位置]
错误：[完整关键输出]
请区分系统权限、沙盒、审批与外部授权，
给出最小范围的下一步，并说明判断依据。
```

如果只是读错目录，就改用正确路径；需要额外访问时，解释任务与范围，再走当前环境支持的授权流程。团队策略限制则交给管理员确认。

## 避免两个常见做法

不要先给整个目录设置所有人可写，也不要默认关闭沙盒。两种做法都可能掩盖根因，并扩大与本次任务无关的访问范围。

**完成检查：** 能说明哪一层限制被处理，重试原动作后确认结果，而不是只看到设置保存成功。
