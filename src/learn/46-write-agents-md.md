# AGENTS.md 模板

下面是一份适合小项目的模板。把方括号替换为项目实际信息，删除不适用项，再保存到项目约定的位置。不要保留猜测的命令。

```markdown
# 项目说明

## 项目用途
[一句话说明这个项目解决什么问题]

## 目录与技术
- 入口：[实际文件]
- 主要目录：[目录和职责]
- 技术：[从项目确认的语言、框架]

## 运行与验证
- 启动：[实际命令；无需启动则写明]
- 测试：[实际命令；暂无则写明]
- 构建：[实际命令；不需要则写明]
- 手工验收：[关键操作和预期结果]

## 修改约定
- 保留与本次任务无关的改动。
- 沿用现有风格，新增依赖前说明必要性。
- 不修改生成文件；修改对应源文件。
- 不在代码、日志和说明中写入密钥。

## 结果报告
- 列出主要改动和原因。
- 区分检查通过、失败与未执行。
- 说明剩余问题，不用“已完成”掩盖限制。
```

## 网页练习怎样填写

入口写 `index.html`，样式写 `style.css`；启动方式写“浏览器打开 index.html”；没有自动化测试，就如实写明，并补充宽屏、窄屏和联系链接的手工检查。

## 写完要验证

让 Codex 读取后概括规则，处理一个小任务，观察是否遵循。项目命令变化时同步更新；写错的规则比没有规则更容易反复误导任务。
