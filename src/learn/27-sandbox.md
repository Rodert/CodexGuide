# 沙盒与审批

沙盒限制操作能到哪里，审批决定哪些操作需要进一步确认。两者配合使用，但不是同一个开关。

例如，Codex 能修改项目文件，却不能访问网络：文件权限允许，网络权限仍有限制。登录账号正常，也不会自动解除这类限制。

## 先区分是哪一种失败

| 提示或现象 | 优先检查 |
| --- | --- |
| 文件只读、无法写入 | 目标路径与文件系统权限 |
| 访问网络被拒绝 | 网络策略、域名与代理 |
| 等待允许执行命令 | 当前审批请求的动作和范围 |
| 管理策略禁止修改 | 团队或管理员约束 |

同样是“没有完成”，解决方法可能完全不同。不要看到失败就把所有权限调到最大。

## 遇到请求时怎么判断

先看完整命令和工作目录，再看它会写入哪里、是否联网，以及为什么需要这一步。比如安装项目已声明的依赖，与把整个目录上传到未知服务，影响并不相同。

不理解时可以直接问：

```text
请解释这条命令的作用、写入位置和联网目标。
有没有只处理当前项目、影响更小的替代方法？
先解释，不继续执行。
```

## 什么情况下需要管理员

个人配置不能保证覆盖组织策略。若设备、工作区或服务由团队管理，先确认约束来源。也要记住：写在提示词里的“不要删文件”是任务要求，真正的系统权限仍由环境控制。

**判断练习：** 先让 Codex 说明给个人网页改标题需要读取和修改哪些文件，再执行这一个小改动。有审批请求时对照核对，没有请求则查看最终差异。正常只需要项目内相关文件；如果它要修改系统设置或读取其他项目，就先要求说明必要性。

本节不要求通过扩大权限来制造成功。发生拒绝时记录原文，再判断是路径不对、网络受限还是需要额外审批；无法确认就保留现场，转到 [权限与沙盒问题](./50-permissions.md)。
