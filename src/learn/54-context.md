# 上下文与任务问题

Codex 忘记要求、反复改错位置或一直处理不相关文件时，先整理任务边界，不必立即换模型或重置整个环境。

## 按现象处理

| 现象 | 可以先做什么 |
| --- | --- |
| 继续沿用已取消方案 | 明确作废旧方案，重新说明当前要求 |
| 修改无关文件 | 缩小文件范围，要求先说明相关位置 |
| 多轮仍无进展 | 要求汇总证据、尝试结果和缺失条件 |
| 对话混入多个目标 | 为独立目标新建任务并交接 |

## 用一条消息重新对齐

```text
先暂停继续修改，重新对齐当前任务。
唯一目标：[内容]
相关文件：[位置]
保持不变：[限制]
已作废方案：[旧要求]
验收方法：[具体操作]
请先检查当前文件，说明已完成、未完成和下一步。
不要根据旧聊天猜文件状态。
```

如果它仍在同一条路上反复失败，要求说明每次尝试改变了什么、结果如何，以及是否有新的证据。没有新信息的重复重试通常无助于定位问题。

## 换任务前保存什么

记录目标、文件、改动、检查结果和剩余问题。文件内容保存在工作目录里，聊天记录不应成为唯一的项目说明。

新任务接手后，先检查实际状态和已有修改，再继续。不要为了“上下文干净”直接删除文件或丢弃未提交改动。
