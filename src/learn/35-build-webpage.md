# 用 Codex 做一个网页

这一节沿用入门时的个人介绍页，把它完善成一个小作品。重点是学会分轮开发，而不是一次塞进全部需求。

## 第一轮：把范围定清楚

准备 `codex-first-project`，先查看已有文件；如果已经做过入门练习，就在原页面上继续。

```text
请完善当前个人介绍网页；如果目录为空，则创建 index.html 和 style.css。
内容使用虚构信息：小林，兴趣为阅读、旅行、摄影。
分为介绍、技能、作品、联系四个区域，作品使用三张文字卡片。
只使用 HTML 和 CSS，不引入依赖、外部字体或图片。
已有内容应保留。先说明计划，再实现并列出修改文件。
```

做完先打开网页，确认四个区域和资源引用正确，不急着继续加功能。

## 第二轮：根据看到的问题调整

缩窄窗口，观察卡片是否挤在一起、文字是否溢出。再给出具体需求：

```text
宽屏时作品卡片横向排列，窄屏时改为一列。
保持文字和链接不变，避免横向滚动。
请说明调整的 CSS 规则；能预览时检查宽屏和窄屏，不能时明确说明。
```

比起“高级一点”“再好看一点”，布局、间距和可见性更容易检查。每轮只改一类问题，发现不满意也容易回退。

## 第三轮：检查交付

检查四项：内容完整；宽窄屏可读；链接目标正确；没有意外新增依赖。联系按钮使用 `mailto:` 时，不要把它描述成已经实现邮件发送后台。

最后让 Codex 写一段简短 README，说明文件用途、打开方式和已知限制；再按 [Git 教程](./31-git-github.md) 保存版本。

**完成标准：** 别人拿到这个目录，不需要询问你，就能按说明打开页面并理解哪些功能已经实现。
