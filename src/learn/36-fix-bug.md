# 用 Codex 修复报错

用一个小问题练习排错：HTML 能打开，样式却没有生效。目标不是让 Codex 重写网页，而是找到证据，修复真正出错的位置。

## 准备一个可复现问题

先保存网页的正常版本。在练习副本里，保留文件名 `style.css`，将 HTML 的样式引用临时改成：

```html
<link rel="stylesheet" href="styles.css">
```

刷新页面，原来的颜色和布局应消失。这个例子里的错误是文件名不一致，故意多写了一个 `s`。

## 给 Codex 提供现象

```text
个人网页能打开，但样式没有加载。
复现：打开 index.html，页面没有原来的颜色和卡片布局。
预期：加载现有 CSS，恢复原页面样式。
请检查引用关系，找到原因后做最小修复。
不要重写页面，不要新增依赖；报告原因、修改位置和验证结果。
```

合理的排查应先对照 HTML 引用和实际文件，再决定修改。若有浏览器工具，还能检查资源加载错误；不能使用时，就报告只完成了文件检查。

## 验证修复是否有效

在这个练习中，将引用改回 `style.css` 即可。重新加载后，检查样式恢复且内容未变；同时查看 Diff，正常只需改动引用位置。

如果刷新后仍不正常，再检查浏览器缓存、实际打开的文件路径和 CSS 语法，不要立刻认定需要更换技术方案。

**学到的方法：** 稳定复现问题，区分预期与实际，用证据定位原因，最小修改后再复现验证。真实报错也沿用这个过程。
