# 修复报错模板

报错信息只是线索，能稳定复现的步骤更有用。先整理“如何触发、预期是什么、实际是什么”，再让 Codex 排查。

## 复制后填写

```text
请排查并修复下面的问题。

环境：[系统、运行时、依赖版本或浏览器]
复现步骤：[从什么状态开始，依次做什么]
预期结果：[应该发生什么]
实际结果：[发生了什么]
错误信息：[完整关键报错及前后文，先脱敏]
近期变化：[最近改过什么，不知道则写未知]

要求：
1. 先复现或核对证据，区分原因与猜测。
2. 找到根因后做最小修复，保持无关行为不变。
3. 适合自动化验证的 Bug，补充能捕获它的回归测试。
4. 重跑相关检查；不能复现或验证时说明原因。
5. 总结原因、改动位置、验证结果和剩余问题。
```

## 信息不齐怎么办

不知道版本就写“不知道”，让 Codex 从项目文件和可用命令确认。不要为了填满模板猜一个版本；没有日志也可以先提供发生时间和具体操作。

如果命令因环境限制未运行，就不能把“修改看起来合理”写成“修复已验证”。请求需要的最小条件，再继续核实。

**验收方式：** 用同样步骤再次操作，原问题消失，相关功能仍正常；新增测试应能区分修复前后的行为，而不是只检查代码是否存在。
