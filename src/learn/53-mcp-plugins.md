# MCP 与插件问题

“安装了但不能用”不一定是安装失败。按能力是否加载、服务是否启动、认证是否有效、调用是否成功的顺序检查，更容易定位。

## 分层检查

1. **安装与启用**：当前入口里是否存在并启用了目标插件或服务。
2. **任务加载**：当前任务能否看到对应工具，是否需要按提示重新加载。
3. **服务连接**：本地服务能否启动，远程地址是否可达。
4. **授权范围**：是否登录正确账户，是否允许访问目标资源。
5. **具体调用**：参数、资源标识和返回错误是什么。

工具列表出现了某项，只说明它被发现，不代表后面的四层都成功。

## 用最小任务验证

先执行一个无敏感信息的只读查询，不要第一次就批量写入。如果失败，收集：

```text
入口和版本：[内容]
插件或 MCP 服务：[名称和来源]
现象：[工具不可见 / 连接失败 / 授权失败 / 调用失败]
关键错误：[脱敏内容]
最小复现：[一次具体操作]
请先定位失败层，不重装、不输出凭证、不放开全部权限。
```

超时可能涉及网络或服务启动，认证错误可能涉及账户或权限；以实际日志为依据。不要把所有问题都归到“模型不支持”。

## 防止修好一个、弄坏其他配置

调整前记录当前配置，一次只改一个变量。来源不明的服务地址和脚本先核实，不把密钥贴在截图、聊天或仓库里。
