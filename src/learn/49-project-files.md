# 项目与文件问题

“Codex 说改好了，但我看不到”，先查目录和保存位置，不要立刻要求重新生成整个项目。

## 文件到底在哪里

先保留当前页面和任务，不继续生成文件。打开你认为的项目文件夹，再按下面的请求拿到完整路径；最后从那个路径重新打开 `index.html`，对照浏览器当前页面。不要只凭窗口标题相同就认为是同一份文件。

让 Codex 报告当前工作目录、目标文件的完整路径和主要文件列表，再与文件管理器对照。同名项目副本、worktree 和云端任务，可能对应不同位置。

```text
先不要继续修改。
请说明当前工作目录、本次改动文件的完整路径，
以及这些文件是否实际存在。
如果有 Git，检查当前分支和改动状态；不要覆盖或清理文件。
```

## 按现象排查

| 现象 | 常见线索 |
| --- | --- |
| 只有聊天代码，没有文件 | 任务可能只返回示例，需要明确要求保存 |
| 文件存在，页面未变化 | 打开了旧副本、未刷新，或预览服务指向别处 |
| 代码改了又被覆盖 | 修改的是构建产物、生成文件或被其他任务写入 |
| 云端结果本机没有 | 尚未取回对应提交、分支或改动 |

浏览器缓存也是可能原因，但先确认打开的是正确页面和目录，再处理缓存。否则强制刷新也不会显示另一个副本里的改动。

**成功的判断：** Codex 报告的路径、文件管理器中的位置和浏览器打开的文件一致。如果某个环节指向副本，改用正确位置再刷新；仍不一致时提供三处路径和观察结果，隐藏真实用户名即可，不必上传整个项目。

## 不要用清理来猜问题

先保存已有修改，再决定是否需要重新构建或重启预览。不要让 Codex 自动删除整个目录、重新克隆或覆盖所有文件来“恢复正常”。

**完成检查：** 你能从完整路径找到真实文件，并能解释预览页面如何使用它。
