# 远程开发与服务器排错

在本机启动 Codex，不代表它已经进入服务器。远程排错前，先明确命令在哪里运行、连接的是测试环境还是生产环境，以及允许做哪些操作。

## 从只读检查开始

准备主机或环境标识、部署目录、服务名称、发生时间和错误现象。凭证通过团队批准的方式配置，不要直接贴进提示词或公开日志。

可以先这样发起任务：

```text
排查测试环境中网页服务无法访问的问题，先做只读检查。
确认当前主机、工作目录、进程、监听端口和相关日志。
按“现象—证据—可能原因”报告。
不要重启、安装软件、修改配置或访问生产数据库。
```

先核对连接目标。服务器上可能有多个版本、容器或相似目录，改错位置可能完全看不到效果。

## 按层排查

1. **连接层**：主机和端口是否能访问。
2. **进程层**：应用是否启动、是否反复退出。
3. **应用层**：配置、依赖和外部服务是否正常。
4. **入口层**：反向代理、域名和证书是否指向正确目标。

比如应用在本机端口能响应，但域名返回错误，就继续检查入口链路，不要直接重写业务代码。

## 修改前后分别记录

先记录配置备份、当前版本和恢复方法，再执行最小修复。之后既检查进程，也检查真实请求；“重启命令成功”不等于“服务恢复”。

**完成检查：** 你知道改了哪台主机上的哪个文件，并能用与用户相同的入口验证问题是否消失。
