# AGENTS.md

同一个项目里，你可能会反复提醒 Codex：“用中文回复”“不要修改生成文件”“改完要运行测试”。这些长期有效的项目约定，可以写进 `AGENTS.md`。

它是给编程 Agent 阅读的项目说明，不是程序代码，也不会因为写了“必须测试”就自动执行测试。

## 应该写什么

优先放入能指导实际操作的信息：项目结构、启动与测试方法、允许修改的范围，以及团队的重要约定。例如在练习项目根目录创建：

```markdown
# 项目约定

## 技术与文件
- 使用原生 HTML 和 CSS，不新增依赖。
- 页面入口是 index.html，样式在 style.css。

## 修改要求
- 保留已有姓名、兴趣和联系链接。
- 修改前确认相关文件，避免无关改动。

## 验证
- 预览桌面和窄屏布局。
- 无法打开浏览器时，说明未验证的项目。
```

## 怎样确认它被理解了

在项目中开始新任务，让 Codex 先概括适用的项目约定，再做一处小修改。看它能否说明约束，并在结果中报告验证情况。

大型项目可能在子目录中放置更具体的说明。排查规则冲突时，要同时检查项目根目录和目标文件所在目录的指引，不能只读一份就推断所有文件的规则。

## 不要写成愿望清单

“代码要优雅”很难验收，“不要新增依赖；修改后运行指定检查”更具体。不要写入密钥、过期命令，或把所有历史需求都堆进去。

一次性需求放在当前任务里；稳定的项目规范再进入这个文件。完整模板见 [AGENTS.md 模板](./46-write-agents-md.md)。
