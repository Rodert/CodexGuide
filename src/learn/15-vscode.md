# VS Code 中使用 Codex

## 适合谁

主要在 VS Code 中阅读和修改代码，希望在编辑器里完成 Codex 工作流的读者。

## 为什么在编辑器里使用

VS Code 的优势是项目文件、正在编辑的代码和改动对比都在同一处。对已有项目而言，这能减少在终端、文件管理器和浏览器之间切换。

## 开始前

通过 [Codex IDE 官方说明](https://developers.openai.com/codex/ide/) 确认扩展入口与支持的编辑器，在扩展页面核对发布者。安装并登录后，打开练习文件夹，而不是只打开一个孤立文件。

先打开一个练习项目或可回退的仓库。第一次不要选择最复杂的生产项目，也不要在不了解改动范围时直接接受修改。

## 基本使用方式

### 从当前文件开始

打开一个你能看懂的文件，先让 Codex 解释它的作用、输入输出和相关文件。确认它理解上下文后，再提出一个小修改。

### 明确选中范围

当你只想讨论一段代码时，说明“只处理当前选中的函数”或“不要修改其他文件”。范围越明确，后续检查越简单。

### 查看改动

编辑器里的改动仍需要你自己审核。重点看：修改是否只发生在预期文件、逻辑是否符合目标、项目能否正常运行。

## 做一个小练习

1. 在 VS Code 选择“打开文件夹”，打开 `codex-first-project`。
2. 在左侧文件列表点开 `index.html`，确认是自己的网页。
3. 在 Codex 扩展的输入区发送下面这条只读请求。

可以先发送一条不修改文件的请求：

```text
解释当前 index.html 如何引用 style.css，暂时不要改文件。
```

确认它读取了正确文件后，再让它只调整联系按钮的颜色。这样能先验证项目上下文是否正确，再开始修改。

保存改动，在浏览器重新打开或刷新对应的 `index.html`。如果扩展返回的是建议而没有实际改文件，先查看当前界面的应用修改入口；不能确认时直接问“是否已保存到文件”，不要把一段建议当成交付结果。

## 与 CLI 怎么配合

编辑器适合阅读、定位和查看 Diff；CLI 适合终端命令、脚本和自动化。两者不必二选一，可以根据当前工作位置切换。
